Case study: Web‑based music‑generation tools

Introduction
Generative music applications let musicians explore harmonic and melodic ideas directly in the browser. They commonly blend algorithmic composition, interactive interfaces, and—at times—machine learning to support composition and practice. This case study examines three modern web apps—Jazz Hero, Strudelizer, and Musical Call & Response—covering their goals, user experience, technical architecture, and opportunities for expansion.

1. Jazz Hero
Overview
Jazz Hero is a headless application with a Django REST API and an Angular front end. The flow is straightforward: choose or create a chord progression and root key, set filters such as approaches, line density, and song cycles, then generate a melodic line for practicing scales, approaches, and arpeggios. Registration is optional for exploration; an account is required to save progressions.

User interface and features
The generator provides separate sections for Treble and Bass lines. Users can:

  • Choose a chord progression via drop‑downs (e.g., blues forms), with support for adding custom progressions.
  • Select line density (eighth‑note or sixteenth‑note) to control rhythmic complexity.
  • Fine‑tune parameters using sliders for song length (cycles), rest density, octave range, note repetition, and approach repetition. An "Approaches" panel toggles various melodic motions (short descents, ascents/descents, "mini" variations, and arpeggios) to shape contour.
  • Set patterns and bass options mirroring the treble controls.
  • Generate and audition a new line, with options to listen and download MIDI.

Angular Material components power the sliders and menus, and the overall layout evokes a compact DAW‑style control surface that encourages experimentation.

Technology and architecture
Backend. A Django API exposes endpoints for progression management and line generation. The generator appears to rely on rule‑based phrase assembly and sample‑based playback rather than machine learning. The headless API is reusable for other clients.

Frontend. Angular (with Angular Material) renders controls and issues REST requests. A service worker may cache assets for limited offline use.

Workflow. Submitting the form POSTs the selected parameters to the API and returns either a MIDI file or a structured representation rendered via Web Audio or for download.

Evaluation
Strengths

  • Customizable generation. Rich parameterization (density, rests, approaches) supports focused practice on specific techniques.
  • Headless architecture. Clear separation simplifies reuse and potential mobile integration.
  • Practice‑first focus. The messaging emphasizes using generated lines for study rather than one‑click "improv."

Opportunities

  • Notated feedback. Adding staff or piano‑roll views with tempo‑adjustable playback would speed evaluation and learning.
  • Style breadth. Beyond jazz‑blues, support for modal, bebop, or arbitrary chord changes would broaden applicability.
  • Explainability. Tooltips and example phrases could clarify how each "approach" affects output.

2. Strudelizer
Overview
Strudelizer converts live MIDI input into Strudel (a live‑coding environment) syntax. Users play notes on a connected MIDI device or on‑screen keyboard and immediately see Strudel code that mirrors their performance.

User interface and features

  • Key & Scale controls. Users set tonic and choose from Western scales (e.g., pentatonic, major, natural/harmonic/melodic minor, diminished) and a range of Indian ragas (e.g., Bhairav, Bhairavi, Yaman), which drive both the keyboard and an XY pad.
  • Visual keyboard & XY pad. The keyboard reflects enabled notes; the XY pad captures controller gestures for expressive data.
  • Strudel MIDI Coder. Users select a MIDI device, clear captures, choose musical vs. integer notation, set sound presets, and adjust tempo and quantization resolution. A status area counts captured notes and shows the active device.
  • REPL integration. A code editor displays generated Strudel syntax with quick actions to copy or load into an online REPL. Keyboard shortcuts support play/stop.
  • Status displays. Panels report MIDI, audio, and general app status; utilities refresh or log devices.

Technology and architecture
Entirely client‑side JavaScript:

  • Web MIDI API for device detection and input capture.
  • CodeMirror for the editor/REPL interface, with Strudel's web REPL package for parsing/execution.
  • Modular structure (e.g., midi handling, coding, audio engine) for maintainability.

As the user plays, the MIDI handler translates notes into Strudel syntax (e.g., [c4, e4, g4]), applies quantization and tempo, and injects the result into the editor for immediate audition or reuse.

Evaluation
Strengths

  • Hardware‑to‑code bridge. Real‑time conversion lowers the barrier between instrumental performance and live coding.
  • Scale diversity. Inclusion of Indian ragas alongside Western modes invites cross‑cultural exploration.
  • Tight workflow. Integrated REPL enables instant playback and iteration.

Opportunities

  • UI simplification. Collapsible sections or inline help could reduce initial complexity.
  • Onboarding docs. Embedded guidance on Strudel syntax and typical patterns would help newcomers.
  • Immediate audio. A lightweight built‑in synth for the on‑screen keyboard/XY pad would meet expectations for instant feedback.

3. Musical Call & Response
Overview
Musical Call & Response combines interactive synthesis (Tone.js) with a Magenta MusicRNN back end to generate AI replies to user‑played "calls." Two input modes—keyboard and a circular, color‑coded wheel—let users craft a melody. The app then produces a response using a recurrent neural network (or, optionally, exact replica or reverse strategies). Scale systems span both Western modes and Indian ragas.

User interface and features

  • Scale selection. Users choose from major (Ionian), natural/harmonic/melodic minor, diminished, and several ragas (e.g., Bhairav, Bhairavi, Yaman, Kafi, Asavari, Todi, Purvi, Marwa, Khamaj, Kalyan). Selected scales activate allowed notes in the input interface.
  • Call input. A chromatic keyboard labels each key with note name and shortcut; a toggle reveals the circular interface, whose segments map to the scale tones. The call is visualized and can be copied.
  • Sound controls. Users select waveform (sine/square/saw/triangle), portamento, and volumes for a beat feedback synth and for an optional drone (with independent waveform).
  • Response controls. Choose Magenta (AI), Exact Replica, or Reverse; adjust number of steps, temperature (randomness), match/extend call length, and whether to clear or append after generation.
  • Generation flow. Status indicators show model loading and readiness; generation decodes the output sequence and plays it via Tone.js.

Technology and architecture

  • Client libraries. Tone.js for synthesis; @magenta/music for loading a pre‑trained MusicRNN (the commonly used "basic_rnn" checkpoint); D3.js for the circular wheel.
  • Scale logic. Arrays of semitone offsets define each scale/raga; selecting one filters the interactive UI accordingly.
  • Inference pipeline. The app records MIDI note values/durations for the call, then runs inference with user‑selected step length and temperature. Non‑AI modes bypass the model for deterministic replies.

Evaluation
Strengths

  • Cross‑cultural scales. Western modes and Indian ragas invite tonal exploration beyond familiar systems.
  • Creative control. Switching among AI, exact, and reverse responses—plus step/temperature—offers flexible practice and play.
  • Intuitive inputs. Keyboard and circular wheel suit different thinking styles; visualization aids review and copying.
  • Sound design. Waveform, portamento, drone, and beat feedback shape the character of calls and responses.

Opportunities

  • Model breadth. Offering alternative checkpoints (e.g., MelodyRNN variants or Music Transformer) could enrich phrasing and longer‑range structure.
  • Performance. Clear progress indicators and smarter caching would mitigate model load/generation latency.
  • Parameter clarity. Brief tooltips (e.g., explaining temperature and steps) would improve usability.

Conclusion
These three applications illustrate complementary approaches to web‑based generative music:

  • Jazz Hero emphasizes parameterized practice within jazz harmony, exposing the mechanics behind melodic shape and density.
  • Strudelizer links performance and live coding by translating playing into executable code, enabling instant remixing and algorithmic manipulation.
  • Musical Call & Response blends user control with AI creativity across Western and Indian scales, offering multiple response strategies and sound‑design options.

Collectively, they demonstrate how browser technologies can democratize music creation and learning. Future improvements—such as broader model options, richer visualizations and notation, clearer documentation, and performance optimizations—would further elevate accessibility and musical depth.
