From p5.js Bézier‑curve Sketch to AxiDraw Pen Plotter

This case study explains how a generative p5.js sketch that builds a set of Bézier curves can be exported to a pen plotter workflow. It looks at the algorithm used to generate the curves, how to export the design as a vector file, modify it in Inkscape, convert it to G‑code and visualise it, and finally draw it with an AxiDraw v3 pen plotter.

1. Creating a Bézier‑curve design in p5.js

1.1 Algorithmic construction of the curves
The provided sketch builds two closed shapes (shape1 and shape2) defined by arrays of anchor points and control vectors. In setup, the code chooses random grid intersections for each anchor and snaps coordinates to the grid spacing using a helper function snapToGrid. The function randomSnappedControlPoint picks a random angle and distance around each anchor, creates a temporary control vector and snaps it to the grid, ensuring that the Bézier handles align to the same grid. Each shape thus has n anchors with associated control vectors. The sketch later draws cubic Bézier segments between consecutive anchors; symmetric control points generate smooth transitions.

The draw loop performs interpolation between the two shapes. It computes an interpolated shape by linearly mixing the anchor positions and control vectors of shape1 and shape2 by a slider value t (0‒1). For each interpolated shape, the sketch optionally computes a colour gradient by interpolating between two user‑selectable colours using lerpColor. It then draws a closed loop of Bézier curves with drawClosedLoop(). A toggle button controls whether the intermediate shapes display control points; another slider controls the number of transitional shapes to be drawn, producing layered gradient lines. Because all anchors and control points are snapped to the grid, the resulting curves maintain consistent spacing and a structured appearance.

1.2 Exporting as SVG from p5.js
To move the design into a vector‑graphics workflow, the sketch uses the p5.plotSvg library. This library is designed specifically for exporting SVG files tailored for path‑based output devices such as the AxiDraw pen‑plotter. The library writes SVG files that describe only the geometry of paths rather than their visual style, reflecting the fact that plotting machines interpret line paths physically. Because p5.plotSvg does not interfere with p5.js's normal graphics output and is easy to add to projects, it provides an unobtrusive way to record the drawn shapes. When the sketch's "SVG export" button is pressed, it creates a temporary SVG graphics buffer, replays the drawing commands into that buffer and uses save() to download the resulting SVG.

2. Editing the vector design in Inkscape

After exporting the design, the next step is to refine it in a vector‑editing program. Inkscape is a free, open‑source vector graphics editor whose workflow is based on vector objects. It includes tools for creating rectangles, ellipses, stars, polygons and spirals, and these objects can be filled with solid colours, patterns or gradients. Inkscape also provides Bézier and calligraphic tools for drawing curves and allows transformations such as moving, rotating, scaling and skewing. The Edit Path by Node tool supports editing individual nodes and handles of Bézier paths. These features make it straightforward to open the exported SVG, adjust control points or proportions, combine or remove paths, and add annotations or layout marks. Inkscape's primary file format is SVG, and it can export to many other vector and image formats, making it a good intermediate step before generating machine code.

3. Converting SVG to G‑code

3.1 Using Universal G‑code Sender (UGS)
To drive a CNC machine or pen plotter, the vector drawing must be converted into G‑code. The Universal G‑code Sender (UGS) is a free, cross‑platform application for interfacing with CNC controllers such as GRBL, FluidNC and TinyG. UGS runs on Windows, macOS, Linux and Raspberry Pi and includes a configurable user interface with a 3D G‑code visualiser that colour‑codes segments and shows real‑time tool‑position feedback. It supports real‑time overrides, a built‑in G‑code editor and a designer editor that can optimise G‑code (removing comments, truncating decimal precision and converting arcs to line segments). Users can load the edited SVG or DXF into a plugin or a separate CAM tool to convert the paths into G‑code, then open the resulting file in UGS.

3.2 Previewing with NC Viewer
Before plotting, it is good practice to verify the G‑code. NC Viewer is a web‑based G‑code simulator and viewer. According to an overview of G‑code simulators, NC Viewer offers a simple yet powerful interface for visualising G‑code programs and simulating tool movements. It provides real‑time rendering of the toolpath, allowing users to analyse the machining process dynamically and includes features like zooming, panning and layer highlighting for better analysis and understanding of the G‑code data. By loading the G‑code into NC Viewer, the designer can confirm that the sequence of moves matches the intended drawing and that there are no unexpected rapid moves or tool plunges.

4. Plotting with AxiDraw V3

The final stage is to physically draw the design with an AxiDraw pen‑plotter. The AxiDraw V3/A3 is a larger version of the AxiDraw V3 and is designed to write or draw on 11×17‑inch (A3) paper. It is described by its manufacturer as "the original simple, modern, precise and versatile pen plotter," capable of writing or drawing on almost any flat surface. The machine can hold fountain pens, permanent markers and other implements and has a writing head that extends beyond its base so it can draw on objects larger than the machine itself. AxiDraw plotters support a variety of applications; the V3/A3 model includes custom‑made aluminium extrusions and precision‑machined components for improved precision and robustness. Using the AxiDraw's companion software, the user loads the G‑code generated earlier, chooses a pen, secures the paper and runs the plot.

4.1 Why pen plotters?
Plotting the generative design with a pen plotter allows the smooth Bézier curves to be realised as continuous ink lines rather than rasterised pixels. Because the p5.js sketch snapped control points to a grid, the resulting curves have a mechanical quality that translates well to plotting. The gradient‑based layering can be reproduced by swapping pens or by drawing multiple passes with different inks.

5. Summary of the end‑to‑end workflow

  • Generate the artwork. In p5.js, random grid intersections produce anchor points, control points are placed on the grid and smoothed by snapping functions, and the sketch interpolates between shapes with colour gradients. The design is recorded as an SVG using p5.plotSvg, which exports the geometry of the paths.
  • Refine in Inkscape. Open the SVG in Inkscape, use node and path tools to fine‑tune curves, combine or split paths and adjust layout. Inkscape supports a wide variety of vector shapes and transformations and allows direct editing of Bézier nodes.
  • Generate G‑code. Use a CAM extension or plugin to convert the edited SVG into G‑code. Load the file into Universal G‑code Sender, which includes a 3D visualiser, real‑time overrides and G‑code editing options.
  • Verify toolpaths. Preview the G‑code in NC Viewer to ensure the toolpaths follow the desired pattern and that there are no collisions or unwanted motions. NC Viewer provides real‑time toolpath rendering and interactive controls for analysis.
  • Draw on AxiDraw. Secure paper on the AxiDraw v3, load the verified G‑code, choose pens and run the plotter. The pen plotter's ability to draw on almost any flat surface and its extended writing head make it suitable for large or unconventional media.

Conclusion

This pipeline demonstrates how generative code can be transformed into tangible artwork through careful consideration of algorithms, file formats and hardware capabilities. Each tool plays a specific role: p5.js enables procedural composition; p5.plotSvg records vector geometry; Inkscape refines and prepares the artwork; UGS converts and previews machine instructions; NC Viewer verifies toolpaths; and the AxiDraw physically renders the design.
